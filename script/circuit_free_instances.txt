# Free public inputs — the reviewed exception list for script/circuit_instance_derivation.py
#
# Format:  <zk source path> : <instance name> : <host-side mechanism that makes it safe>
#
# WHAT BELONGS HERE. A `constrain_instance(X)` where X is a witness the circuit does not derive
# and does not bind, AND where the host (`*_entrypoint*` / `get_metadata` in the contract crate)
# constrains X by some means the `.zk` source cannot show — almost always by comparing it against
# chain state. The third field must name that mechanism concretely enough that a reviewer can go
# and read it. "The contract checks it" is not a mechanism; a file, function and condition is.
#
# WHAT DOES NOT BELONG HERE.
#   * X that the circuit derives, or binds via constrain_equal_base  → classified, no entry needed.
#   * X that feeds another exposed determination                → classified `redundant`.
#   * X where no host-side mechanism was found. Leave it failing. Growing this file is the act
#     that grants the exception, so an entry whose justification was not actually verified is
#     worse than a red gate — it is precisely the Orchard-class bug wearing an audit badge.
#
# Each line below was checked against the Rust by reading it, not inferred from the name.

# --- the oracle aggregate's declared bounds (OBL-Z16) --------------------------------------
# `aggregate.zk` exposes `min_result` and `max_result` and uses them only against `result`
# (`diff_max = base_sub(max_result, result)`, `diff_min = base_sub(result, min_result)`, each
# `range_check(64)`ed at :161, :165) — a check over three values the prover picks, so the
# in-circuit half constrains nothing on its own. The host half is what makes the expose safe
# to let through: `aggregate_v1` re-checks the same relation on the *params* and rejects by
# name, so a proof cannot carry a result outside the bounds the transaction itself declares.
# The honest limit, stated rather than implied: the bounds are the operator's own declaration
# about its own output, and the operator already chooses `result` — the four `value_i` and
# `weight_i` are prover-chosen too (`aggregate.zk:220-224`, OBL-Z1) — so these two grant no
# freedom the `result` expose did not already grant. The chosen alternative, not taken, is to
# register bounds on chain and compare against the record; that is a new field on a genesis
# contract's record, which is a design change rather than a repair.

# --- bearer_bond coverage report: FREE BY DESIGN, and no host check exists ------------------
#
# These four lines are different in kind from every line above them, and the difference is the
# point of writing them down. Every other entry records a host mechanism that constrains the
# exposed value — a state lookup, an equality against chain state, a length the host counted.
# Here there is no such mechanism, and none can exist: the values are the issuer's *claim about
# its own off-chain reserves*. Nothing on chain can check a reserve balance, so the honest
# classification is that the prover chooses all four and discloses them.
#
# What the proof does contribute, and why these are exposed rather than left as witnesses:
# `ProveCoverage_V2` constrains `coverage_ratio_bps * total_obligation <= reserve_amount * 10000 <
# (coverage_ratio_bps + 1) * total_obligation` over exactly these four values, so the report is
# arithmetically consistent with itself. Before this, only `tx_binding`/`tx_nonce` were instanced
# and `coverage_ratio_bps` was a plain witness: the host read it from call data and nothing checked
# it at all. An issuer could publish any reserves it liked *and* any ratio at all. Now the ratio it
# publishes must be the ratio of the amounts it publishes. What the proof still does not establish
# is that those amounts are true.
#
# Consequence, recorded rather than implied: `is_coverage_voided` is an issuer-controlled switch.
# An issuer that wants emergency unstake to be reachable reports reserves below the obligation; an
# issuer hiding insolvency reports the opposite. The remedy would be an anchor the issuer cannot
# choose — a series reserve account the contract holds and totals itself — which this contract does
# not have. Until it does, a coverage report is an attestation and should be read as one.
src/contract/bearer_bond/proof/prove_coverage.zk : reserve_amount : host: none — issuer's claimed reserve balance; bearer_bond entrypoint/mod.rs:1063-1066 stores it verbatim and `is_coverage_voided` (validation.rs:52, called at mod.rs:903 and :1077) voids the series when the ratio is < 10000; there is no on-chain quantity to compare it against
src/contract/bearer_bond/proof/prove_coverage.zk : total_outstanding : host: none — issuer's claimed outstanding principal; stored verbatim by mod.rs:1063; the contract keeps no running total of stake principal to compare against
src/contract/bearer_bond/proof/prove_coverage.zk : total_interest_obligation : host: none — issuer's claimed accrued interest; stored verbatim by mod.rs:1064
src/contract/bearer_bond/proof/prove_coverage.zk : coverage_ratio_bps : host: none — the governance datum, stored verbatim (mod.rs:1066) and consumed by validation.rs:52 `is_coverage_voided`; the circuit proves only that it is the ratio of the three amounts above, which the issuer also chooses
