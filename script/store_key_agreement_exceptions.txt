# Adjudications for `scripts/check-store-key-agreement.sh` — the rule that a state record's writer
# and its readers agree about the key.
#
# Format, one entry per line:
#
#   <rel path> | <tree constant> | <normalised read key> | <reason citing the mechanism>
#
# `|`-delimited, not `:`-delimited: a key can contain `::` (e.g. `IntentCommitment::from_base(...)`),
# which a `:`-split truncates. A key cannot contain a `|`; the reason is the free-text tail and may.
#
# Content-keyed on path, tree and key — NOT on line numbers — so a file that shifts underneath an
# entry keeps its adjudication, the same choice `circuit_tx_pair_last_exceptions.txt` and
# `circuit_dead_value_exceptions.txt` made and for the same reason. A declared entry that no longer
# matches a finding is reported by the checker, so this list cannot outlive its sites.
#
# THE LIST IS A RATCHET, NOT AN AMNESTY. Every entry here is a read whose key does not textually
# match any write in the same file, and each one is either (a) a real writer/reader disagreement —
# the class `OBL-C199` records, four instances of which the `bearer_bond` migration found one at a
# time across separate ~950-second runs — or (b) a legitimate asymmetry that the reason must say so.
# An entry whose reason is "unclear" belongs in neither column: it is an open question, and the
# honest thing is to leave the gate reporting it.
#
# TRIAGED 2026-10-07 — all 28 sites read, and the gate is now BLOCKING. The first run reported 26
# undeclared; triaging found exactly one live defect — `stablecoin`'s `b"last_interest_accrued"`,
# written nowhere and read inside `if let Some(...)`, so a `HAZOP CRIT-1` defense-in-depth check
# never ran (fixed; it cleared the gate's own finding, 27 → 26). Two were genuine NO-WRITERs:
# that one, and `bridge`'s `b"current_timestamp"` (recorded in `OBL-C199`, deferred contract). Every
# other one is a false positive of a shallow textual gate — one field reached through two names
# (`escrow.commitment`/`escrow_id`), a stored field vs a derived id (`stake.table_id` vs the init
# `poseidon_hash`), or the record's own identity field (`fund.id` vs `params.fund_id`). None was a
# defect. Triaging also found **two defects in the gate itself**, both fixed with self-test cases:
# `db_mark_spent` was filed as a *read* though the SDK defines it `db_set(db, key, &[1])` (so any
# nullifier tree looked writer-less — that hid `dao_escrow`'s, `labor_market`'s ×2, `oracle`'s and
# `stablecoin`'s ×2 behind a skip), and the `params.`/`update.` prefix strip was anchored at `^`, so
# the same field inside a call argument never matched (that hid both `relayer_endowment` ones).
