# Circuits `check-circuit-metadata-alignment.sh` checks on TWO legs instead of three.
#
# The invariant that script enforces is three-way — the circuit's `constrain_instance` order,
# the `get_metadata` arm's push order, and the client's `to_vec` — and it has always been able
# to compare only the first two when it cannot locate the third. Until 2026-10-04 it printed a
# bare `OK` in that case, on 48 of 166 circuits (29%), which is OBL-C79's shape — a green line
# covering a third of the tree — sitting inside the check whose own header cites OBL-C79 as the
# incident that taught the repository to print coverage. It now prints `OK(2/3)`, counts the
# rows, and fails on an *undeclared* unresolved client.
#
# Format, one entry per line:
#
#   <contract>/<circuit> : <why the third leg is unchecked here>
#
# THIS IS A DEBT CENSUS, NOT A SET OF ADJUDICATIONS, and the distinction is the whole point of
# the file. An entry says "the client's public-input vector for this circuit was not located, so
# the circuit's order was never compared against it". It does **not** say the site is sound, and
# it must not be read as one: an ignored mismatch here is a proof the verifier refuses, which is
# exactly the failure this campaign has spent three test runs on. The two reasons below are the
# only two in the list, and neither is a judgement about the circuit.
#
# ACQUITTAL IS BY REPAIR, NOT BY DECISION. An entry leaves this list when the circuit's vector is
# found — named in `CLIENT_ALIASES`, added to the resolver, or the client written by whichever
# session owns that contract. It does not leave by being argued sound.
#
# Measured 2026-10-04. Register row: OBL-C198.
