# DarkFi Terminology

Precise terminology for DarkFi smart contract development.

## ZK Circuit Terms

| Term | Definition |
|------|------------|
| **Namespace** | Unique identifier for a ZK circuit (e.g., `CreateClaim_V1`, `CreateAttestation_V1`) |
| **Witness** | Private inputs to a ZK circuit, known only to the prover |
| **Public Inputs** | Inputs known to both prover and verifier (e.g., commitments, nullifiers) |
| **Proof** | Cryptographic proof generated by the prover, verifiable by anyone |
| **Verification Key (VK)** | Public key used to verify proofs |
| **Proving Key (PK)** | Secret key used to generate proofs |
| **ZK Circuit** | Arithmetic circuit that proves computation correctness |

## ZKAS/ZKVM Terms

| Term | Definition |
|------|------------|
| **ZKAS** | ZK Assembly - human-readable circuit description language |
| **ZKVM** | Zero-Knowledge Virtual Machine - executes ZKAS circuits |
| **.zk file** | ZKAS source file containing circuit definition |
| **.zk.bin** | Compiled ZKAS binary (used by ZKVM) |
| **zkrunner** | Developer CLI tool for interacting with ZKVM |

## Contract Terms

| Term | Definition |
|------|------------|
| **Function Enum** | Enum mapping function IDs (e.g., `0x00`, `0x01`) to contract functions |
| **Params** | Function parameters (public inputs to the ZK circuit) |
| **Update** | State change returned by contract execution |
| **State Tree** | Merkle tree storing contract state (keys/values) |
| **Nullifier Tree** | Merkle tree storing spent nullifiers (prevents double-spending) |
| **Bulla** | Unique identifier for a coin/UTXO in DarkFi (from "burn" + "leaf") |

## Transaction Terms

| Term | Definition |
|------|------------|
| **Transaction (tx)** | Bundle of contract calls with proofs and signatures |
| **ContractCall** | Single contract function invocation |
| **CallLeaf** | Leaf in the transaction call tree (proved in ZK) |
| **Proof Verification** | Verification that a ZK proof is valid |
| **Fee Call** | Special contract call that pays transaction fees |
| **Signature** | Ed25519 signature authorizing transaction |

## Privacy Primitives

| Term | Definition |
|------|------------|
| **Pedersen Commitment** | Hiding + binding commitment: `C = g^a * h^b` |
| **Poseidon Hash** | ZK-friendly hash function used in DarkFi |
| **Merkle Tree** | Cryptographic accumulator for efficient membership proofs |
| **Bulletproofs** | Short non-interactive zero-knowledge proofs |
| **Range Proof** | Proof that a value lies within [0, 2^n) |

## DarkFi-Specific Terms

| Term | Definition |
|------|------------|
| **O-Cap** | Object Capability - privilege model where access is controlled by possession of capabilities |
| **Object Capability** | Unforgeable reference that grants specific access rights |
| **Bulla** | Unique coin/UTXO identifier, prevents double-spending |
| **zk证明** | Chinese for "ZK proof" |
| **Token ID** | Identifier for a fungible token type |
| **Serial** | Secret value used to derive nullifier (prevents double-spend) |

## Contract Development Terms

| Term | Definition |
|------|------------|
| **Entry Point** | Function called by validator to execute contract logic |
| **WASM** | WebAssembly - contract deployment format |
| **SDK** | Software Development Kit - client-side API for contracts |
| **Test Harness** | Framework for integration testing contracts |

## Common Patterns

| Term | Definition |
|------|------------|
| **Commit-Reveal** | Two-phase pattern: commit hash first, reveal value later |
| **HTLC** | Hash Time Locked Contract - timelocked refund with hash reveal |
| **Merkle Proof** | Path from leaf to root, proves membership |
| **Nullifier** | Unique identifier for spent coins, prevents double-spend |
| **State Channel** | Off-chain transaction mechanism (future work) |
